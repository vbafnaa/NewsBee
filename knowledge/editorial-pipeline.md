- The Next.js [journalist workspace](../apps/journalist-site/app) manages locations, source maps, story runs, and editorial review. Source discovery builds a location's map. Story collection reads that map for an edition window.
- The Operations location directory's primary **Manage sources** action opens `/locations/<id>?tab=sources`, the existing editor. `/locations/<id>/source-map` remains a secondary, explicitly read-only inspection destination; neither navigation action starts source discovery.
- The `current` and `agentic` flows share assembly, ranking, authoring, and publishing. The agentic flow adds mapping tools, topic sweeps, and tracing to primary sources. See [source discovery](../apps/journalist-site/README.md#source-map-and-discovery) and the [scraping playbook](../playbook/README.md).
- Start with the [orchestrator](../apps/journalist-site/pipeline/orchestration/orchestrator.ts) for stage and retry behavior, the [connectors](../apps/journalist-site/pipeline/connectors) for source-specific collection, and the [pipeline tests](../apps/journalist-site/pipeline/tests) for regression coverage.
- [Cloud job delivery](../apps/journalist-site/README.md#how-a-run-works) always uses the existing private Vercel Queue for kickoff, Resume and immediate/delayed continuation, including cold consumers. Signed HTTP recovery executes at most one job before queue handoff; failed handoff returns 503 without discarding completed work. There is no cloud HTTP-chain fallback: queue acceptance is not consumer delivery, and unavailable consumers require operator attention. Local HTTP handoffs and polling remain unchanged; claims, idempotency and paid-replay guards remain in the orchestrator.
- [Execution deadlines and recovery receipts](../apps/journalist-site/README.md#how-a-run-works) bound model dispatch/fallback/quota waits with settlement headroom. Rating/editor-order and agent model operations retain run/content/policy/model-scoped receipts; unknown dispatched outcomes block automatic paid replay. Agent search/proposal operations checkpoint individually and expose bounded checkpoint measurements. Within-run stage concurrency remains unchanged; full diagnostic normalization still requires measurements.
- [Ranking](../apps/journalist-site/README.md#ranking-v5-and-voice) captures versioned engagement/acceptance evidence once per draft, batches independent item updates, projects authored-entry summaries and uses identical incremental MMR. Rights, withdrawals and governance remain live checks; query-index rollout still requires live inventory/explain evidence.
- [Search cache freshness](../Docs/search-cache-freshness.md) uses provider-origin time across search, similar and explore calls, never renewed query-use time. [Collected-item retention](../Docs/collected-item-retention.md) preserves numeric timestamps and proposes BSON Date expiry without enabling TTL deletion; historical reference review and explicit migration approval remain required.
- Story collection prepares the edition for review. Explicit publishing hands it off to the [reader](publishing-and-reader.md).
- Journalists work in assigned newsrooms and create editions, not newsrooms or locations. From a newsroom they may also review that newsroom's communities in a newsroom-scoped Inbox and Source map, and start a source run (Collect sources) for a community the newsroom covers, paid from the newsroom-managed allowance ([scope](../apps/journalist-site/pipeline/publications/newsroom-scope.ts); `prepareManagedBinding` and the map-run route recheck coverage). The binding records the newsroom and the run records who started it. A location's source map is shared by every newsroom covering it; decisions and added sources record who made them, while pausing, pinning and windows stay operator-only. [Newsroom creation](../apps/journalist-site/pipeline/orchestration/create-newsroom.ts) rechecks the persisted Admin/Owner role before provisioning and inside the creation transaction. Creation retains deliberate creator ownership but adds no member assignments. `canManageNewsrooms` is an operator-management predicate, not a publication membership or support grant.
- The journalist workspace gives each view a real route under `/newsroom/<publicationId>` ([routes](../apps/journalist-site/app/newsroom/newsroom-routes.ts)): Overview, `/new-edition`, `/editions`, `/editions/<draftId>` (the editor), `/generation` (activity and recovery), `/videos` (with Video Studio under `/releases/...`) and `/settings`. The [newsroom layout](../apps/journalist-site/app/newsroom/[publicationId]/layout.tsx) keeps the edition workspace and Settings mounted across these routes. Older `#editions`, `#settings`, `#generation-activity` and `?draft=<id>#…` links redirect from Overview; on the bare newsroom path a hash still selects its view. Explicit draft identity lives in the editor route. Its publication-scoped history pages through 50 drafts at a time, retaining same-window regenerations and corrections. Polling never replaces the selected draft; missing or foreign draft IDs do not fall back to another editor. Generation run IDs remain separate from selected draft IDs.
- **New edition** offers **Generate draft** or **Start writing**. Manual drafts use `POST /api/admin/publications/<id>/drafts` with `locationIds`, an exact seven-day `window` and body `idempotencyKey`. Actor/publication/key identify one durable draft; changed details conflict. Current enabled/write and selected-within-allowed Ready coverage are rechecked. Draft/audit persistence is atomic, `origin` is `manual`, and `generation_id` is absent: no generation, run, job, provider call or funding record is invented. A string-only partial unique generation index replaces the old unconditional index before manual drafts can coexist; existing generated drafts and correction/release contracts remain compatible.
- The publication route lands on **Editions**, with **Settings** as the other primary task; there is no competing Overview view. Editions shows a compact dated/status history list with explicit **Open / Open current** controls and retained paging, not hidden select options. Opening an edition reveals its retained writer without the history list above it; **All editions** returns without discarding editor buffers. The writer has one concise edition context with truthful save/revision state, one lifecycle-specific next-stage action and secondary optional preview. **Generation activity and recovery** is a separate secondary destination (`#generation-activity`), not a navigation accordion. Active, paused, blocked, cancelling and failed work stays immediately signposted. Legacy `#overview`/`#home` reveal the Editions list; reporting/stage/story anchors open the writer, including asynchronous exact targets. `#delivery`/`#audience` reveal Settings and focus coverage. Native fragments, chooser handoffs and browser back/forward preserve exact draft/generation selection and unrelated queries.
- The [edition list](../apps/journalist-site/app/publishing/publication-generation.tsx) uses saved titles with dates/status, not generated-draft labels or truncated IDs. The [retained published edition](../apps/journalist-site/app/publishing/publication-editorial-workspace.tsx) shows read-only story copy and a direct **Video Studio** handoff alongside live/history links; it does not promise autosave or request approval again. Correction/withdraw/restore remain explicit and guarded. Studio links use the selected immutable release, omit withdrawn/correction-required releases, and never generate on navigation. The [story chooser](../apps/journalist-site/app/publishing/[channelId]/releases/[releaseId]/release-distribution.tsx) returns to the server-resolved exact draft and retains authored UUID story IDs. [Story video controls](../apps/journalist-site/app/publishing/[channelId]/releases/[releaseId]/video/[storyId]/release-video-manager.tsx) say **Create script and captions**, collapse full source copy/hashes/provider policy, and keep quota, funding, access, errors and side effects explicit. Generation, MP4 upload/download and review gates are unchanged. Newsroom editions may include their own optional Save the Bee game before publication; videos remain separate from Reader copy.
- Only the selected view is visible or focusable. The generation/editor stays mounted; Settings defers first mount, and its secondary coverage and Source feedback disclosures load only on first opening. All stay mounted hidden/inert thereafter, retaining pending inputs, errors and failed/dirty values. The header summarizes the selected draft, never the latest unrelated generation, and never marks an editing draft's Review complete. Saving newsroom settings configures future publication, not approval or immediate publishing. Shell sign-out actions remain server-side.
- [The canonical editor](../apps/journalist-site/app/publishing/publication-editorial-workspace.tsx) shows a desktop story outline or compact accessible mobile chooser beside **one active story**. Story/task switches and section reassignment retain story-keyed articles and auxiliary image/private-note buffers; section settings never own story component identity. **Add story** immediately opens that same surface and focuses its headline; repeated clicks reuse the one unconfirmed story, and no server story is created until input changes. Blank titles display **Untitled story** only. The sole section/location may default; multiple choices and public bylines are never inferred. Edition headline/intro live in **Edition details** and explicit Save the Bee controls under **Optional extras**, both after the writer. Sources, section/location, images, private notes and generated evidence are on demand; corrective review links reveal the relevant disclosure and focus its required control. Plain story links still focus the article itself. Missing requirements and holds remain linked and visible.
- Original autosave extends the existing `add_original_story` operation with a canonical UUIDv4 `storyId`. Incomplete original text, sources, locations and section can persist without placeholder data, with exact text retained. Creation records an actor/payload receipt atomically with the story: same-payload retries can confirm a lost response at a stale revision, but changed payload/actor, ID collisions and removed-story retries conflict. Later story patches keep strict revision checks. The browser queues later typing behind first confirmed identity, preserves failures for explicit retry and never announces Saved before persistence. Legacy omitted-ID complete-story creation retains its prior strict validation/server-ID behavior. Included unfinished stories remain included and fail authoritative readiness/preview checks, including an unassigned section; a blank not-yet-created editor also blocks readiness/preview until typed or removed.
- Generation funding/readiness, allowance and shared admission use a separately guarded preflight; failure, exhaustion or occupied capacity disables generation without blocking inspection or manual writing. Shared availability reads the authoritative global blocker rules and current admission lease without reserving, releasing or reconnecting work; paused/blocked/cancelling parents retain their existing semantics. New edition setup rechecks every 15 seconds after each response while visible, aborts on hide and offers an explicit recheck. Availability is advisory: atomic submit remains authoritative, with generic contention/retry messaging that exposes no other newsroom identities or recovery links and never directs admission contention to personal-key settings. Workspace metadata does not resolve or decrypt provider credentials. All configured coverage remains visible; when more Ready communities exist than one edition permits, selection is explicit rather than silently truncating to the first eight. Journalist recovery does not offer personal-key setup. Capability expiry disables writes while retaining attempted reporting forms; server actions still recheck current persisted authority. Live/archive/history links reuse the validated configured Reader base URL rather than assuming Next.js serves Reader paths.
- Switching drafts flushes queued presentation edits through a successful-persistence barrier and refuses failed/conflicted saves, active editorial actions, or unfinished reporting/image/private-note forms. Failed values stay visible for retry; lifecycle actions cannot continue after a failed flush. Each selected draft has a keyed editor and independently cancelled reads.
- Story movement swaps only same-section neighbors within the existing full `story_order`; unrelated section slots/order stay intact, and the explicit Section selector still moves a story between sections. Contextual control names, a concise position announcement and post-save heading focus make boundary moves distinguishable.
- Editorial save status announces state transitions, not every keystroke. **Saved** requires all scheduled, queued, retry and auxiliary image/note work to succeed. Failed draft values remain pending (including validation failures), same-target edits merge rather than erase them, and independent auxiliary failures cannot be cleared by a successful unrelated save. A confirmed validation rejection (HTTP 422) of **Mark ready for approval** or **Reopen for editing** is an actionable workflow error, not unsaved content: it is not retained or replayed ahead of corrective edits, including when encountered during explicit retry. Conflicts, access failures and uncertain transport/server outcomes retain the existing save barrier; corrective content must persist before a deliberate readiness retry, exact-revision approval and separate explicit Publish.
- Story inclusion is separate from retained generated provenance and editable copy. Held stories default to excluded. Only recognized producer quality/style holds can be resolved with a reason, actor, timestamp and atomic publication audit; factual, source/access/rights, content-safety and unknown holds remain non-overridable. Excluded copy/evidence remains editable but never enters readiness or output.
- [Publication generation recovery](../apps/journalist-site/pipeline/publications/generation-recovery.ts) targets `?generation=<id>` independently of `?draft=<id>`. Assigned journalists and deliberately audited support Admins use publication-linked cancel, resume or retry; global run actions remain operator-only. Blocked, paused and cancelling parents retain admission and block ownership transfer. Resume explicitly rechecks current coverage, provider policy and budget; polling never reconnects work.
- Recovery preserves completed children and retries only missing/failed/interrupted work. Another journalist's legacy funding requires an explicit own-funding or managed-sponsorship choice and audited reason; original initiation history remains distinct. Accounting-uncertain paid work cannot be retried or have counters reset. Cancellation denies pending dispatch and retains its slot while any claimed worker remains unsettled, including an expired claim; only settlement or safe fencing permits completion.
- [Provider policy](../apps/journalist-site/pipeline/accounts/execution.ts) follows the current global account role, not the publication context's `editor` label. Assigned stored-editor Journalist accounts use managed services without decrypting legacy personal profiles. Admins always use their own encrypted provider keys, including while assigned journalist rights or performing audited support; missing keys never fall back to platform/environment credentials, even when the historical environment toggle is set. The configured Owner intentionally receives deployed provider credentials by default without a personal credential profile: model execution records `environment` funding, with explicit personal overrides and revocation preserved. Owner Desktop Video intentionally retains its managed fallback (`platform` funding / `managed` identity) when no personal Desktop key is selected; Admins never receive this exception. New generation children, recovery, one-off release-package work and Desktop Video share these role boundaries. Workers recheck active assignment/coverage or explicit support and credential version before dispatch; promoting a Journalist to Admin invalidates its managed execution until deliberate recovery.
- Location run selection is passed to the [inspector](../apps/journalist-site/app/dashboard.tsx), source trace and story items. Selecting or closing a run initiates navigation without waiting for detail requests; polling never rewrites the URL, and selection changes abort the old inspector/trace requests.
- [Execution readiness](../apps/journalist-site/app/api/admin/execution/route.ts) evaluates the newest 200 runs plus at most one explicitly selected `run` lookup before resolving legacy credential policy. This adds visibility, not recovery authority. Global blocker destinations resolve combined children through their stored parent to `/newsroom/{publicationId}`; missing parents have no invented link, and standalone source runs use `collect-sources`.
- [Location readiness](../apps/journalist-site/pipeline/communities/readiness.ts) recalculates current [source evidence](../apps/journalist-site/pipeline/communities/source-coverage.ts) for both the catalog and exact-ID lookup used by preparation transitions, newsroom coverage, generation/recovery and Reader search. An onboarded location with at least one current usable source-map link can be marked Ready; no completed-map timestamp, actual boundary, library/directory association, library source or category completeness is required. Only active/pinned, readable, nonrejected, non-link-only, access-eligible sources count; alternate reviewed endpoints do not gain approval. Coverage gaps remain diagnostics, never aggregate admission locks. Explicit Ready/resume transitions and operator blocks remain; cached coverage and historical editions never replace missing current usable sources.
- Source maps belong to the exact stored `location_id`, not a display name, publication or labelled run. [Source-map inspection](../apps/journalist-site/app/locations/[locationId]/source-map-manager.tsx) displays that ID and empty-map recovery guidance: verify the original run's location and isolated/live storage before another run or any deliberate eligible-source activation. Isolated run records and page labels alone are not current readiness evidence.
- The source-map [live run log](../apps/journalist-site/app/source-map/live-source-run.tsx) and newsroom [generation activity](../apps/journalist-site/app/publishing/publication-generation.tsx) share a compact accessible progress bar, using their existing reads only. Source-map stages follow queued/running durable jobs and execution diagnostics; edition stages follow the parent and its community children. Counts of community drafts are not overall percentages: only `mapped` / parent `ready` fills the bar. Completed children never complete the combined edition. Waiting, blocked, paused, cancelling and terminal failures stop motion; failed status reads retain labelled last-confirmed state. CSS respects reduced motion.
- Journalist generation progress uses plain-language stages/counts and actionable recovery notices, not raw errors, stack traces, job logs or displayed generation IDs. The server newsroom page passes operator presentation from the signed-in principal's global role, never publication membership: assigned Admins retain technical troubleshooting details even when their publication role is `editor`. The operator source-map live log is unchanged; this presentation choice does not change authorization or recovery commands.
- Edition generation's existing newsroom poll also returns a bounded, Mongo-grouped child-work summary: completed source checks and story-writing steps, allowlisted current-step labels, and actual job start/completion times, never job payloads or logs. Story steps are not approved/included story counts or an overall denominator. Last-confirmed activity ages independently of successful reads and parent updates; after five minutes without a confirmed job boundary (or with no evidence yet), the bar stops moving and explains that a longer step may still be running. Failed reads retain labelled last-confirmed evidence; failed/paused/blocked/cancelling states keep attention/recovery precedence. Individual failed source/image checks do not invent a generation blocker. No worker, queue, generation or funding behavior changes.
- Attaching a prepared map means explicitly configuring a Ready location in an existing newsroom's allowed communities **and** edition coverage, or deliberately creating a newsroom with that initial coverage. The location directory links configured newsrooms to coverage separately from People assignment. Coverage reuses the same location map; it never copies sources, grants memberships or publishes. Legacy publication IDs such as `reader-site` remain exact string Mongo `_id` values in output-channel updates/archive/restore, not ObjectIds or generated-only hex identities; lifecycle CAS, account rechecks and immutable-history retention are unchanged.
- Ordinary newsroom landing cards and switcher choices omit archived publications, without hiding paused-but-unarchived newsrooms. An explicitly selected archived workspace retains disabled, labelled selector context; exact newsroom/edition URLs and authorized `publicationId` handoffs still resolve. The underlying directory remains complete for archive management, governance and history.
- The Journalist shell brands itself **Newsbee**. The chooser has one **Your work** heading and publication cards, without a duplicate sidebar picker or empty task navigation. Cards retain exact saved names and show exceptional inspection, coverage-needed and paused states rather than routine direct/active labels. A selected workspace uses its newsroom name as the heading and retains the labelled **Switch newsroom** form, task navigation and account/operator links; stored publication IDs and deep links are unchanged.
- Location Settings exposes optional [evidence repair](../apps/journalist-site/pipeline/communities/evidence.ts) for operators: a current evidence revision, reason and HTTPS provenance accompany actual Polygon/MultiPolygon boundaries and current in-boundary directory outlet selections. Repairs compare-and-swap the stored geography/system evidence, retain boundary provenance through later directory refreshes, and record before/after evidence. Adding a library source still requires an actual current profile system with branches; that source-specific rule does not gate location readiness. Neither a repair nor a source-map run overrides source access rules or explicit preparation blocks.
- Journalists request preparation through the [publication-scoped coverage endpoint](../apps/journalist-site/pipeline/communities/coverage-requests.ts), only for a currently allowed location or for an empty allowed boundary. Retries reuse one request and its original timestamp; requested/preparing/blocked/ready status follows current readiness. Requests join the existing Operations queue but never grant coverage, membership, source approval or reader consent. Operator evidence-remedy links stay out of journalist projections. Collect sources provides the existing editable source map and labels beneath a named disclosure, with a direct link to evidence repair in the same location's Settings.
- Sources have operational Pause/Resume controls separate from review/training labels. Resuming restores pins and dormant retry dates and rechecks access restrictions. Activation checks access before recording a verdict, and saves live status and verdict together; a later page-decision/history failure explicitly reports that the live change was saved. Library links require selection of an actual profile system with branches.
- All sources keeps its existing section groups and All filter defaults in compact, container-responsive rows. Identity, current live/review state, access/health holds and Decision/Reasoning stay outside collapsed source details; full provenance, window, health and model evidence remain available inside. Shared review controls retain their serialized saves/retries and table compatibility for run inspection. Failed, queued and unfinished reviews stay visible through filters, survive unrelated data reloads and cannot have pending text replaced by an older save response. Changing a choice that discards unfinished reasoning asks for confirmation; full-page reload/navigation requires explicit discard while input is unfinished. Read-only inspection has the same source records without mutation controls.
- [Discovery outcomes](../apps/journalist-site/pipeline/discovery/status.ts) prefer optional structured `outcome`/`reason` producer evidence while retaining `ok`, detail and history. Overpass run-policy denial bypasses mirror retries and remains explicitly disabled, as do LLM-off and missing ATTOM configuration. Read-only legacy compatibility accepts the exact old LLM/ATTOM details and only institutions' known-endpoint all-policy-denial Overpass aggregate; mixed/unknown attempts remain failures. Operations and Sources show saved-configuration guidance with raw details under diagnostics, not an instruction to retry disabled services. Saved outcomes do not establish current settings, change eligibility or waive stale-map/readiness alerts; manual refresh and existing due times remain unchanged.
- The location directory keeps geographic state separate from workflow readiness, carries the exact requested ID/name to onboarding, and allows reasoned suspension of ready locations plus resumption through the existing CAS/audited preparation transitions. Suspensions gate future work, not historical Reader releases. Its preflight reuses execution-policy blockers and their real destinations rather than inferring provider/budget readiness.
- [Managed model allowance](../apps/journalist-site/pipeline/model/budget.ts) is one UTC daily pool across initiating journalists, roles and concurrent/child runs. [Execution runtimes](../apps/journalist-site/pipeline/accounts/runtime.ts) reserve through the existing atomic paid-call counter immediately before each provider dispatch, including compatibility retries, fallbacks and vision. Grounded search uses the same reservation through its usage recorder; reads do not reserve. Usage keeps the initiator separate from explicit platform/personal/environment funding. Current-day unclassified history is conservatively included without relabeling it; reserved or unrecorded attempts remain charged when reporting fails. Accounting failure stops fallback rather than issuing another paid request.
- [Health](../apps/journalist-site/pipeline/orchestration/health.ts) displays sanitized managed configuration and recorded observations, never live provider checks. It distinguishes successful mapping/build/publication freshness, historical publication, current live/withdrawn availability, and incomplete cost estimates. The shared budget snapshot is observational; configuration alone does not establish provider or queue-consumer success.
- Admin's **Source inspection** opens the read-only source map, not source management. Its source/run views retain the selected location and run; the workspace handoff opens that location's `sources` or `collect-sources` tab. Inspection never enables edits. Location requests select their own navigation item for `#location-requests` and `#onboarding`; same-page queue navigation preserves request query context.
- Admin separates **Newsletter operations** (`/newsletter`) from **System health & model usage** (`/health`, usage view `/health?view=usage`). Operator links expose their active destination; password/sign-in and server-side sign-out remain separate account actions.
- Campaign review remains read-only with GET filters, 50-request pages and filtered CSV export. Responsive cards keep email, campaign, context, role, interest and signup date visible; full UTM fields live in per-request attribution disclosures.
- Shared journalist controls use the [design tokens](../shared/design-tokens.css) for readable sizing and touch geometry, with explicit compact desktop variants. Original-reporting source fields reflow by available editorial container width rather than only viewport width; nested story panels must not clip fields or focus outlines.
