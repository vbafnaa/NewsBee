- A **newsroom** is the persistent publication/output-channel workspace; an **edition** is one dated draft with review, explicit approval and publication state. Stored destination types retain their existing output eligibility semantics; reference URLs are compatibility metadata, not a separately connected product. The canonical editorial path uses the existing draft/release machinery; no additional workspace entity, editor or publisher is introduced.
- The legacy [publish worker](../apps/journalist-site/pipeline/orchestration/publish.ts) still writes historical per-location edition JSON and the location index to the resolved reader folder. MongoDB `output_channels` controls folder selection; fallback applies when the channel record is absent. Keeping this maintenance machinery does not make it the daily newsroom publisher.
- Publication coverage has an explicit `allowed_location_ids` boundary, managed only by global workspace owners/admins, and a journalist-selected `selected_location_ids` subset. Legacy records initialize allowed communities once from their current selection only, never historical releases, published locations, or the Ready catalog. Publication ownership does not confer workspace administration.
- `/newsroom` is the assigned-newsroom chooser; the persistent newsroom is the existing publication/output-channel ID, not another workspace entity. Creation is available only to workspace Admins/Owners through the Admin directory and is enforced server-side, validates selected communities with `locationReadinessForIds`, and initializes the boundary to exactly that selection. Empty coverage creates a pending-setup newsroom, not a Ready edition. The API limits selections to 1,000 communities and ownership to 100 publications.
- The [safe newsroom directory](../apps/journalist-site/pipeline/orchestration/output-channels.ts) returns minimal summaries and direct/inspection mode without private settings or an audit read for each unopened row. `GET /api/admin/output-channels` returns that directory; full editable `channels` require `?channelId=<id>` and an authorized scoped read. Scoped responses carry authoritative write capability/support expiry. Selector and release/video shells use the same safe directory, including inspectable nonmember newsrooms.
- [Newsroom creation](../apps/journalist-site/pipeline/orchestration/create-newsroom.ts) requires a stable `requestKey`, storing the actor, payload hash and target ID before provisioning. Same-details retries resume the persisted local/Mongo target or preallocated Drive folder ID; changed details conflict. Channel creation, completion and its single audit event commit transactionally with the current account/quota fence. Creation never seeds an empty `locations.json`: existing directory/publication materializers own that file, so a late resumed attempt cannot reset later content. Unconfirmed details and key survive a tab reload until confirmed; success refreshes the directory and selector. Local and Drive-to-Mongo storage fallback remain supported without requiring a connected provider.
- Coverage, boundary, ownership and membership changes share `lifecycle_revision` (legacy missing means zero). Channel PATCH/DELETE requests carry `lifecycleRevision`; stale writes return 409 before artifact cleanup. The channel editor retains failed edits, replaces only the successfully saved channel, and requires explicit confirmation before discarding edits to reload.
- Daily publishing uses the selected edition's explicit workflow in `/newsroom/<id>`. Legacy publishing workspace URLs hand off to this route while retaining draft/generation selection; historical per-location/per-story tools remain labeled advanced maintenance, not another primary publisher. Newsroom coverage configures future edition choices; workspace rename, allowed boundaries and whole-newsroom lifecycle stay in operator management. No settings save publishes or republishes historical content.
- The retained selected-edition editor shows one concise status/revision/included-count context, a lifecycle-specific next-stage link and secondary optional private preview. Editions home is a visible dated/status list with explicit Open/current controls; opening an edition hides the list and **All editions** returns without remounting forms. Old Overview/home links resolve to the list; reporting and stage aliases open the retained writer. Stage links reveal/focus their actual target after loading without changing query selections. The review target remains available in read-only lifecycle states. A single compact **Review edition** issue list links missing headline/introduction, unfinished included stories, sources and media/safety holds; corrective links open the relevant supporting fields and focus the needed control, while plain story links still focus the article. The list is advisory, never readiness clearance. Mark ready, exact-revision approval and explicit Publish remain separate deliberate actions. Private preview is optional and never inferred from approval. Generation diagnostics/recovery have a secondary destination with visible attention notices; generated evidence can collapse, but actual flags/holds stay visible.
- Corrective story links focus the explicitly focusable article, not a nested image/notes summary. Original-reporting guidance permits reopening only for ready/approved drafts; publication-in-progress cannot be edited, and published releases direct journalists to correction/history or a new edition.
- Community removal passes the authenticated operator into publication cleanup. Affected publications compare-and-swap their scope revisions and save principal-attributed configuration hashes in the same MongoDB transaction before any reader/artifact cleanup. Actor-free legacy calls remain valid only when no publication is affected; governance-affecting removal requires an enabled workspace owner/admin.
- Astro serves the public app under `/reader`. Start with [reader data access](../apps/reader-site/src/lib/reader-data.ts) for edition loading and [pages](../apps/reader-site/src/pages) for routes and handlers.
- The public application root redirects to `/reader` without authentication; `/newsroom` and `/admin` remain explicit operator routes. Reader location search includes published coverage snapshots even when the location is absent from today's setup directory. A covered location opens the existing independent-newsroom chooser; no newsroom is chosen on the reader's behalf. Uncovered communities retain the existing consented coverage-interest capture, never automatic generation or publication.
- Independent publications use an explicit draft approval and publish state machine. Publishing writes one immutable, content-hashed release artifact plus an immutable versioned manifest, then compare-and-swaps the compact `reader_publication` pointer. Corrections create successor releases; withdrawal and restore actions append availability history without changing release content.
- [Release validation](../shared/publication-release.ts) accepts exact multiline article bodies (`blurb`, up to 20,000 characters, including LF/CR/tab) like the editorial writer; other C0 controls and DEL remain rejected, and identity/headline fields remain single-line. Parsing never normalizes text or rewrites historical payloads/hashes. New publisher payloads must pass the same parser before a publish claim. Latest/exact release routes own HTTP 502 for integrity/storage failures and 404 for missing release/story selections; child rendering components do not set response status.
- The editions discovery API, global browse/search/history, and location chooser use [legacyReaderDiscovery](../apps/reader-site/src/lib/reader-data.ts) to treat only the typed [disabled legacy channel](../shared/reader-folder.ts) error as an intentionally absent legacy source, allowing independent publication discovery. The channel stays disabled and is never bypassed with a fallback folder. Malformed channels, missing MongoDB settings, database/storage failures and invalid absent-channel fallback configuration still log and return 503. The existing valid fallback remains restricted to an absent channel document; explicit legacy reads/publishers still reject disabled channels.
- Publication home shows the seven-day calendar only when at least one displayed day has an event, not merely when an editorial section is named `events`. Service guides and out-of-window stories remain unchanged in All stories and archive counts. Reader media credits/details use neutral **Image** and **Date** labels, preserving saved credits (including AI disclosures) without inferring photographic capture or rewriting releases. The shared email-availability policy hides publication newsletter promotion on reading pages; the header instead opens All stories. Direct signup/status and historical preference/unsubscribe routes remain unchanged.
- Save the Bee is optional per newsroom edition in the existing editor: journalists explicitly save their chosen word and hint (3-12 letters; 8-180 character hint excluding the answer). The game participates in revision/readiness/approval content hashing, exact authenticated private preview, immutable release snapshots and Reader rendering. Omitted games and older release hashes stay compatible. Browser responses mask answers until normal game completion; preview attempts are revision-scoped and cannot share results. Publishing never imports community-edition games. Public games reuse the existing seven-day/latest-edition scoring window, browser save cookie, six-miss rules and server scoring; no automatic game generation or provider call is added.
- Generated photo and illustration binding reuses reviewed pipeline eligibility and requires available immutable assets; URL normalization alone never grants reuse rights. Unavailable, unreviewed, or revoked media carries a visible review reason rather than silently gaining permission. Included stories require replacement or an explicit no-image choice before readiness or preview. Corrections atomically clone eligible referenced media into new correction-owned image records and IDs, leaving source draft/release assets untouched; replacement and removal remain local to the correction.
- Draft-history indexes allow multiple unpublished drafts per publication. Release identity is unique only where `release.release_id` is a string; index initialization installs that partial unique index before removing the legacy compound sparse index, which incorrectly indexed unpublished drafts too.
- Readiness, approval, release snapshots and private preview share the included-story selector; empty included editions are rejected and empty excluded sections do not leak into output. Explicit writes safely migrate legacy unpublished selections: a changed selection bumps the revision, reopens editing and clears approval/claims. Publishing rechecks included-story safety and current media eligibility against the approved snapshot; published releases remain immutable.
- Private draft preview uses the actual Reader publication components at `/reader/publications/<publication-id>/drafts/<draft-id>?revision=N`, not a duplicate editorial mockup. The authenticated preview API and private media bridge recheck current publication access and exact revision; stale, conflicting or unavailable selections never fall back to latest. Responses are private/no-store, with no release artifact, pointer, invented publishing timestamp, provider call or email. The workspace requires successful persistence before opening and hides the captured preview on edits or revision changes.
- [Reader URL resolution](../apps/journalist-site/pipeline/publications/preview.ts) keeps optional link configuration separate from both generations and selected-draft GETs: metadata includes `readerBaseUrl` and explicit `readerLink` availability. Rejected nonempty configuration returns a null base and safe persistent warning, never a fallback link; permitted manual creation/edit/save and readiness/access rules remain unchanged. Deliberate link retries refresh metadata without replacing pending/failed edits. Strict private preview still rejects invalid configuration after exact-revision/access/media checks. Missing/blank values retain `/reader`; HTTPS roots and `/reader/` normalize consistently, and the HTTP loopback exception remains local-only.
- Invalid Reader configuration diagnostics distinguish malformed/nonabsolute URLs, credentials, query/fragment and disallowed HTTP without exposing the configured value. A nonempty relative `/reader` is rejected; missing/blank alone gets the same-origin fallback. Deployment administrators correct `NEWSBEE_READER_SITE_URL` for the actual Reader origin and activate it through an approved `main` deployment; Retry workspace links only reloads metadata. Profile homepage and destination references cannot repair it. See [operator remediation](../Docs/deployment.md).
- `/reader/locations/<location-id>` maps one location to any number of independent publications. Publication latest, archive, exact-release, section, event, and story routes read the compact manifest directly, verify artifact hashes, preserve publication-time profiles, sections, sponsors, and location tags, and do not pass through legacy edition or Bee gates.
- A newsroom's default edition is its full combined published release, with every covered community named, not a location-filtered edition. The chooser links to this existing renderer and the edition archive; explicit legacy `?location=...&edition=...` and exact publication release links retain their semantics.
- Public publication reads and discovery allow `enabled === true` or a finite numeric `archived_at` with `archived_was_enabled === true`. Archiving a previously disabled/nonpublic newsroom does not grant public access. Reader destination, published pointer, manifest/release integrity and withdrawal behavior remain required: no latest is resurrected, while exact withdrawn releases retain their visible withdrawal notice. Reader never modifies publication artifacts to support history.
- Global browse/search indexes each publication's current release while immutable history remains available once through exact release and archive links. This avoids parsing every historical artifact on each request and does not mutate or duplicate legacy Reader editions.
- Reader browse reuses freshly listed channel rows, coalesces in-flight immutable manifest/release loads, and limits artifact I/O to six concurrent reads per instance. Only verified immutable values are cached; current publication directory/enabled/pointer reads are not availability-cached. Community/exact-edition filters run before latest-release item reads, and historical coverage is filtered from manifest entries rather than today's pointer locations.
- Legacy selected-location/edition routes bypass the bulk 60-second catalog cache. Canonical exact editions read only their file and the current directory; latest-location pages and metadata-only directories probe bounded scalar headers before selecting bodies. Normal publisher payloads do not require unrelated item bodies. Reordered/oversized external JSON retains a full-parser compatibility fallback. [Reader read-path bounds](../apps/reader-site/README.md#reader-read-path-bounds) documents probe limits and the remaining work: unfiltered global search/history still scans catalog metadata and matching current/legacy bodies; strict page-bounded body work needs a maintained public index, not stale availability caching.
- Publication headers and footers return to publication home; section/story and signup-return links retain the exact release. Explicitly labeled links leave for global discovery. [Publication navigation helpers](../apps/reader-site/src/lib/publication-view.ts) validate contribution context against the published release. Share/source forms require a deliberate covered-community choice for multi-community releases, not the first location or a client-supplied return URL.
- Email is unavailable across the applications, regardless of provider credentials. [Shared availability copy](../shared/email-availability.ts) accompanies disabled send/campaign/email-preview/confirmation controls. Guarded POSTs return 503 before new email writes; historical campaign GETs and signed preference/unsubscribe management remain available without activating pending subscriptions. See [email availability and capture](../Docs/newsletter-delivery.md). Community preference capture remains working without confirmation mail; marketing lead capture remains separate. No delivery schedule or production provider is introduced.
- The deployed `/reader/campaign/newsroom`, `/reader/campaign/college-journalism`, `/reader/campaign/high-school-journalism`, and `/reader/campaign/branded-news` entry points remain separate marketing flows. Their form posts to [the campaign signup API](../apps/reader-site/src/pages/api/campaign-signups.ts), which validates the selected campaign, records sanitized UTM attribution, and uses a SHA-256 campaign/email key for idempotent writes to `campaign_signups`.
- Authoring reports email output as explicitly unavailable while the product gate is off: no email-purpose inference, preview rendering or new HTML/text artifacts, including recovered and combined-location child runs. Website front-page work and historical email/consent records remain independent; see [newsletter delivery](../Docs/newsletter-delivery.md). Their form posts to [the campaign signup API](../apps/reader-site/src/pages/api/campaign-signups.ts), which validates the selected campaign, records sanitized UTM attribution, and uses a SHA-256 campaign/email key for idempotent writes to `campaign_signups`.
- Campaign capture and publication discovery share the single exported `readerMongoClient()` connection cache. Campaign writes use only `campaign_signups`; publication discovery reads release pointers and artifacts from `output_channels` and `output_channel_files`.
- Check [shared JSON schemas](../shared/contracts) when changing the publish payload. Public editions expose story source links. Editorial source maps and run diagnostics stay internal.
- Reader styling uses the existing publication/legacy renderers and exact release or draft links, retaining profile branding, event calendars, sponsor slots, email availability and private-preview boundaries. [Story conversations](../apps/reader-site/README.md#reader-navigation-and-story-conversations) use separate MongoDB records for published-article comments/helpfulness; canonical reader validation and full-lifetime site-writer admission keep private/withdrawn content and restore maintenance out of the public write path.
- [Publication settings](../apps/journalist-site/app/publishing/publication-settings.tsx) requires a successful initial read before editing. Profile is primary; writing preferences and sponsors have separate disclosures, saves and dirty indicators. Voice/story length enter future generation snapshots and story-writing prompts, never rewrite current drafts or manual copy. The combined edition's headline/intro belong to Editions: the Front intro preference only changes unused child-front output, so its control is omitted alongside unavailable Email intro while both stored/API values are preserved. Failed saves preserve local values/errors; reloading requires discard confirmation. Successful saves replace only the saved block. Settings/source-feedback writes use authoritative direct/support capability and expiry; server mutations recheck access.
- Newsroom primary tasks are **Editions / Settings**. Reporting belongs to the single retained selected-edition editor in Editions, with visible edition history/selection and a desktop outline/mobile chooser for one active story. **Newsroom coverage** is the secondary Settings disclosure: its saved selected-community set bounds future editions within the operator-managed allowed boundary; an edition can then choose a subset without changing newsroom coverage. No duplicate workspace rename, enabled/lifecycle, allowed-boundary or reference URL inputs appear in normal Settings. Operators retain the real name/lifecycle/boundary controls at `/admin/publications/<id>`. Destination URLs are not editable in either surface but remain intact in storage/API payloads. Settings and coverage load lazily and stay mounted hidden/inert, preserving pending selections, search and failed saves. Old `#delivery`/`#audience` aliases reveal/focus coverage without changing draft/generation/query context. Source feedback/history retain their lazy state. **Save newsroom coverage** changes future edition choices only, never existing drafts/releases or approval/publication; its notice asks users to save unfinished work and reload before starting another edition so the retained generation chooser refreshes its coverage metadata.
- Publication source feedback displays stored `approved` as **Acknowledged - source change pending**, with the actual review note; acknowledgement never changes the shared source. Release distribution prioritizes optional video, with read-only delivery history secondary. Email remains unavailable and no history disclosure activates sending.
- Profile settings are real: private preview uses current saved branding; explicit publication captures profile and enabled sponsor revisions in the immutable release/Reader pointer. Reader home consumes display name/description/logo; the shell uses homepage as the Publisher website link. Enabled sponsors render in two fixed home slots, never ranking/provider input. Later saves do not republish or rewrite history. The internal workspace name is managed separately. Destination types retain Reader eligibility; retained URL strings have no current routing/provider consumer and are deliberately absent from Settings.
- Video Studio is the existing publication-release story workflow: `/video-studio` opens the newsroom chooser at release history, then **Editions → Publication releases → Open/Inspect Video Studio and delivery history → Open video workspace**. Opening it does not generate anything. GET exposes direct/support write capability and support expiry; read-only/expired clients disable package writes, uploads, replacements and provider polling, while server mutations still recheck authority. Global Admin remains personal-funded even when assigned; assigned Journalists use managed services and the Owner retains deployed defaults/personal overrides. Generated/uploaded videos remain separate assets; they are not inserted into immutable Reader releases or email.
- Save the Bee remains a current community-edition product using location/edition IDs and reviewed `bee_games`. Publishing a newsroom release never automatically inserts or imports a community game. The new-edition default is intentionally implemented as browser-local tomorrow through six days later; no reporting-window policy is changed here.
