- The exact `NEWSBEE_OWNER_EMAIL` identity is the immutable owner. Owners manage admins and editors; admins manage editors only. Effective identity is reloaded from `journalist_admins` on each request, and publication access remains tied to stable principal IDs.
- Google OAuth remains available to enabled approved accounts. Editor username/password setup requires a provisioned account and a 72-hour, single-use invitation. Only invitation hashes are stored; passwords use bcrypt with cost 12. Credential login is throttled by hashed username and IP identifiers.
- Access management projects only safe password states: setup required, setup link issued/not completed, expired, or credentials set, with pending recovery shown separately. An expiry marker retains setup history after token TTL cleanup; status never claims a link was delivered or setup completed merely because an operator issued it.
- Manual recovery uses one-hour, single-use links issued by an enabled owner for admins/editors or an enabled admin for editors only. No operator can issue recovery for the immutable owner, and disabled targets must first be deliberately re-enabled. Owners recover their own access through approved Google sign-in and the account password surface, not another operator. Issuance rechecks the persisted issuer and target, serializes with suspension/demotion, checks the Access revision, and records a secret-free audit event.
- Recovery links are shown only in the deliberate issuance response for manual copying/sharing; no email is sent. They use 32-byte random tokens with SHA256 hashes at rest. The reset page transports the secret in a URL fragment, removes it from the address bar, and submits it only in same-origin POST bodies; API responses are no-store. Reopening/reloading the page after the fragment is removed requires reopening the original shared link. Never log tokens, request bodies containing them, or the one-time link response.
- A newer signup/recovery link replaces older setup links. Redemption checks expiry explicitly (TTL is cleanup only), enabled status, stable principal ID and credential generation; deleting/recreating an email cannot reuse the original link. Global role changes invalidate pending setup/recovery links, and permanent account deletion removes recovery records. Issuance allows five links per issuer or target in 15 minutes; inspection/redemption/password-change submissions allow eight per IP or token/account in 15 minutes, counting successes too and storing only HMAC identifiers.
- Every signed-in role can open [Password & sign-in](../apps/journalist-site/app/account/security/page.tsx) without gaining provider settings access. Existing credentials require the current password; an approved Google-only account can choose its initial username/password. Usernames already set cannot be changed here. Local demo identities cannot mutate passwords. Success revokes all existing Google and password Newsbee sessions and pending setup/recovery links without changing stable IDs, roles, memberships, publication ownership, content or provider consent.
- Fresh verified Google and password sign-ins bind JWT sessions to the stable Newsbee principal ID, never a provider ID or email lookup on refresh. Legacy email-only sessions require one-time reauthentication. Guarded requests reload enabled status, role and capabilities by that ID; deleting and recreating an email cannot revive the deleted principal's session. Existing account/content IDs and publication assignments are preserved; the restricted localhost-only development bypass is unchanged.
- JWTs also carry `newsbeeSessionVersion`, independent of Access revisions. Principal-bound pre-version JWTs are generation zero until the first password setup/reset/change; email-only JWTs remain unbound. Credential verification checks the original Mongo account, password hash and generation after bcrypt, carries that verified generation through sign-in admission, and never reads a newer generation to bless an old-password login. Refresh/client session updates cannot upgrade a session's generation. Guards reject revoked generations on the next request; unrelated Access edits still resolve dynamically rather than logging users out.
- Full restore independently revokes all prior sessions with `newsbeeRestoreGeneration`, a random deployment generation that archives cannot supply or replace; closing maintenance rotates it too, so old revoked owner sessions cannot regain recovery access. Password verification carries the observed generation through sign-in; JWT refresh cannot upgrade it. Setup/reset rows carry `restore_generation`; pre-generation links are accepted only before the destination's first maintenance closure/restore. While maintenance is closed, only verified Google sign-in for the configured owner can obtain recovery access, using the independently retained owner identity even if the snapshot's account collections are incomplete. Reopening does not reconnect old sessions or restart restored work. See [the full-restore runbook](development-and-deployment.md#full-snapshot-restore).
- Only the workspace owner may suspend or reactivate non-owner global admins through Access management. Suspension denies the next guarded request without changing the stable principal ID, Admin role, publication ownership or deliberate memberships. Reactivation restores access but never reconnects or restarts blocked sponsored runs. The owner remains immutable; admins cannot change their own status or that of peers or the owner. Status changes reuse revision checks, transactions and `status_changed` audit events; global role edits remain separate from status and assignments, and promoting an editor still requires an enabled account and removes editor assignments.
- Permanent deletion is operator-controlled: owners may delete admins or editors, while admins may delete editors. The configured owner is never deletable. Publication ownership blocks deletion until explicitly resolved; memberships, credentials, invitations, Drive consent and active upload state are removed transactionally, sponsored runs and active video jobs are blocked, and append-only access audit records remain.
- The workspace owner may deliberately assign enabled admins to publications; these memberships confer direct journalist rights, independently of support elevation. Promoting an editor still clears the old editor assignments, requiring a new deliberate admin assignment. Membership writes advance the publication lifecycle revision and conflict with ownership transfers.
- Operators switch explicitly between Operations and Newsrooms. The six daily Operations destinations are Locations, Newsrooms, People, Inbox, Marketing and System, with role-appropriate API settings separately accessible. Contextual navigation reuses existing screens without changing permissions. Newsroom cards distinguish direct access from inspection and retain publication-bound governance beside each current/paused/archived newsroom; Owners also retain global audit/ownership history under Newsrooms. Governance suppresses support elevation for directly entitled owners/assigned Admins; unassigned writes still require deliberate, current publication-bound support. Manage journalists opens People with validated newsroom context, not an automatic assignment.
- The Operations newsroom directory keeps non-archived rooms (including disabled rooms) primary and archived newsrooms/legacy destinations in a collapsed maintenance disclosure. Archived inspection is labeled as retained history; People and governance keep the exact publication context. Each row's Maintenance disclosure exposes delivery/storage at `/admin/publications/<id>` and deliberate archive/restore confirmation, without granting membership or support. The maintenance page links back to the directory and publication-bound governance.
- People projects archive status separately from enabled/paused status. Assignment lists label archived newsrooms accurately and group them in a secondary disclosure (opened for an exact archived newsroom handoff); collapsing it never drops existing memberships from an explicit save.
- People uses the user-facing role name Journalist while retaining internal `editor` permissions. A missing username/password is labeled as not set, not as a sign-in blocker; invitation/recovery completion states remain separate.
- Anonymous `/` remains Reader-first; authenticated default sign-in returns Owners/Admins to `/admin` and Journalists to `/newsroom`, whose directory still requires deliberate assignments. Password and Google login share a sanitized same-origin return destination, preserving explicit Reader links and protected deep-link queries. Middleware overwrites the internal return-path header from the actual request; page guards carry it through login. Authentication/API destinations, external URLs and malformed return links cannot become callback targets.
- `/account` is primary Operations navigation: **Environment & API settings** for the Owner and **Personal API keys** for Admins; inside a newsroom, Owners and Admins see the journalist workspace with one role-gated **Operations** link in the user card; the journalist sidebar has no other admin items. Journalists retain Password & sign-in only and cannot access provider settings; newsroom **Settings → API keys** explains that their generation uses newsroom-managed services, while Owners and Admins get the same key editor as `/account` there (the API stays operator-only). Navigation requires no provider keys. Owner deployment defaults and explicit personal overrides remain unchanged; Admin profiles use only their own keys, and deployment secrets are never displayed.
- **Marketing** opens existing **Video campaigns** (`/admin/video-campaigns`) for both Owners and Admins: private, actor-owned promotional briefs, scripts, captions and explicitly paid video requests. Shared Marketing navigation separately exposes **Campaign requests** (`/admin/campaigns`, read-only leads, filters and CSV export) and **Insights / Google Analytics (external)** (the authenticated `/interest-usage` redirect, not an internal analytics dashboard). Editorial **Video Studio** belongs to an immutable newsroom edition, not global marketing; its actions retain publication and execution-policy checks. Opening or saving a campaign never invokes a provider, grants newsroom membership or uses managed Journalist funding.
- **System** opens `/health` with Pipeline, Model usage and Desktop Video tabs; `/health?view=video` reuses the non-secret video diagnostics from the read-only newsletter summary API without presenting an email workflow. Shared System navigation links Storage (`/drive-diagnostics`) and audience/consent/delivery history (`/newsletter`, email unavailable). Owner recovery & Danger zone retains full backup/restore (`/site-backup`, not ordinary import), scoped Reader/source cleanup (`/clear-data`) and the gated local article evaluator. Existing page/API guards and deliberate confirmations are unchanged; navigation performs no writes.
- Source inspection remains contextual to Locations, including the read-only `/source-map` and `/locations/<id>/source-map` URLs and internal gates. Discovery has no separate menu item; `/discovery` still redirects compatibly. Edition map is a read-only funnel/comparison, linked for operators from each exact generation child location/run in a new tab so the original newsroom/edition/generation selection stays open. Inbox retains all review components; direct Neighbour stories and Remembrances URLs identify with Inbox rather than duplicate Owner menu items.
- `/admin` is the location-centric global directory, with source-map health, assignment readiness, newsroom/People handoffs and next actions together. Exceptions are compact; run and intake diagnostics are secondary disclosures. Only Locations is active there; there is no duplicate Operations destination. Owner/Admin context is explicit, and Admin Help links personal settings without reading platform provider configuration.
- Global Admins and Owners manage reversible newsroom archival from `/admin/publications`; this management authority does not grant editorial membership or invisible support. DELETE on `/api/admin/output-channels` now archives, never deletes; PATCH with `action: "restore"` restores. Both require the current lifecycle revision, recheck the persisted enabled global actor inside a transaction, serialize with account/lifecycle changes, and append checksum-verifiable change evidence. Active generation, video/upload, manifest claims and approved/publishing releases block lifecycle changes.
- Archive records `archived_at` (epoch seconds), `archived_by` (stable principal ID) and `archived_was_enabled`, and sets `enabled=false`. Safe channel/directory projections expose `archivedAt: number | null` and lifecycle revision. Restore unsets all archive metadata and restores the previous enabled state, never promoting a previously disabled newsroom. Published artifacts, immutable releases, manifests, pointers, memberships and audit history are retained. Reader eligibility is `enabled=true` or a finite numeric archive marker with `archived_was_enabled=true`, with existing public-pointer/release-availability checks still required. Ordinary disabled records remain nonpublic; settings cannot re-enable an archived record.
- [Publication ownership](../apps/journalist-site/pipeline/publications/ownership.ts) is transferable only by the enabled configured workspace owner, never merely by a publication creator/owner. The successor must be enabled and already deliberately assigned as a journalist or admin. A lifecycle revision and explicit retain/remove choice for the former owner's membership are required; active generation, video or manifest work blocks transfer. Account/ownership writes serialize transactionally with suspension, deletion and assignment changes. IDs, content, release payloads and reader pointers remain unchanged, legacy channel editions acquire their stable publication scope, and the audited transfer retains the actor and successor email snapshots.
- [Access management](../apps/journalist-site/app/admin/access/access-management.tsx) refreshes account revisions after failed remove, invitation, or update requests without clearing the mutation error. A failed recovery read appends its error instead of hiding the original failure; initial-load failures offer Retry.
- Admin pages put explanatory copy and provider configuration under Help. People keeps identity, status, password setup and assigned newsrooms visible, with mutations under each account's Manage access disclosure. Non-owner Admins see Add journalist and manageable journalists before the compact read-only owner/Admin roster; the owner's broader management hierarchy remains. Collapsing disclosures preserves pending form state; successful account revisions reset only assignment inputs, not the disclosure.
- Deliberately issued signup/recovery links appear beside the target account, outside Manage access, with Copy link, expiry, focus/status feedback and No email sent. Clipboard failures remain visible. Results stay only in component memory, survive assignment or unrelated account actions, and are forgotten on reload; issuing a replacement or taking an invalidating account action clears that target's old result.
- `/admin/access?publicationId=<id>&email=<optional email>` supplies context only. The newsroom must match the loaded safe list, email only prefills Add journalist, and assignments still require an explicit revision-checked save. Closed, reviewed journalist-interest inquiries can link to People, but Closed is not approval; the handoff never creates an account, assignment, setup link or consent.
- Owner transfer and audit detail are collapsed; ownership/audit fetch errors and unverified-entry warnings remain visible. Governance verifies the original stored account snapshots before projecting bounded safe fields, never rewrites historical hashes and distinguishes verified, mismatched and unsigned legacy evidence. Checksums remain per-entry evidence, not a complete tamperproof chain.
- The Access HTTP boundary preserves maintenance refusal as private, no-store 503 rather than converting it to an unexpected 500; policy validation, authorization and stale-revision statuses remain distinct.
